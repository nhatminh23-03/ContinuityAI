## Reading this

The two providers agree on the large majority of artifacts, which is expected: most of the corpus
either clearly names a capability or clearly names none, and both methods handle those the same way.

The disagreements are where the interesting information is. `CONTRIBUTION → INDEPENDENT_EXECUTION`
means the model read the narrative and concluded the person acted alone where the rule saw only that
they authored something. That is exactly the judgement a rule cannot make, and it is also exactly the
judgement that most needs checking — promoting a contribution to an independent execution is what
moves an engineer toward `PRACTICED`, and therefore what closes or opens a coverage gap.

**Neither column is automatically correct.** The hidden ground truth decides. Seed and evaluate under
each provider and compare the reconstruction scores:

```bash
AI_PROVIDER=deterministic python -m scripts.seed_demo && python -m scripts.run_evaluation
AI_PROVIDER=cached        python -m scripts.seed_demo && python -m scripts.run_evaluation
```

Until the cache reaches full coverage, `AI_PROVIDER=cached` will refuse to run: a graph half derived
by a model and half by string matching would be neither, and no number in it could be explained by
reference to a single method.

# The verdict: the hidden ground truth decided, and the rules won

Written after running the evaluation under both extractions on the same corpus, same rules, same
everything downstream. The only variable is who read the artifacts.

| Check | Rule-based extraction | Model extraction (`chain_cache.json`, 640/640) |
|---|---|---|
| Knowledge reconstruction (readiness) | **56/56 — 100%** | 54/56 — 96.4% |
| Capability exposure classification | **25/25 — 100%** | 24/25 — 96.0% |
| Critical gap detection | 2/2 — 100% | 2/2 — 100% |
| Declared-vs-demonstrated ownership | 1/1 — 100% | 1/1 — 100% |
| **Counterfactual simulation** | **25/25 — 100%** | **15/25 — 60%** |
| Backup candidate recommendation | **2/2 — 100%** | 1/2 — 50% |
| Evidence grounding | 56/56 — 100% | 62/62 — 100% |

The model extracted **more**: 144 claims against 126, and 62 coverage edges against 56. On a naive
reading that looks like better recall. Measured against the labels, most of the extra coverage is
wrong, and it is wrong in one consistent direction.

## What the model got wrong, precisely

Two readiness values on the hero capability, both **too high**:

```
eng_jordan_lee / cap_incident_recovery   truth EXPOSED   model PRACTICED   (2 buckets out)
eng_maria_gomez / cap_incident_recovery  truth ASSISTED   model PRACTICED   (1 bucket out)
```

Jordan's record on gateway recovery is two years of review comments. Maria assisted, with support. The
model read both as hands-on independent capability.

## Why that single mistake is disqualifying

It is not two cells in a table. Promoting Jordan and Maria to `PRACTICED` gives Incident Recovery a
second and third adequate engineer, so the capability flips `DEGRADED → COVERED`, and the entire hero
scenario stops being true:

```
                              rules            model
Incident Recovery exposure    DEGRADED         COVERED
system index / class          74 / HIGH        (recomputed lower)
simulate Alex unavailable     74 → 93          → 91
critical gaps after           2                1
covered after                 2                3
```

"Alex is the only person who can recover the payment gateway" is the product's opening claim. Under
model extraction it is false — not because the situation changed, but because the model was generous
about two people. The simulation score falling to 60% is that one error propagating.

**The direction matters more than the magnitude.** A continuity tool that overestimates readiness tells
a manager they are covered when they are not. That is the one failure mode this product cannot have:
being wrong in the reassuring direction is worse than being wrong at all, because nobody goes looking
for a problem the tool says does not exist.

## What this settles

**Rule-based extraction stays on the demo path**, and this is now a measured decision rather than a
convenience. The 100% figures are not the rules being flattered by a synthetic corpus — the model had
the same corpus, the same prompt discipline, the same validation gate, and scored worse.

**The model's real value is where it was already being used: the prose.** The narratives are written
over facts the rules decided, and every one passes the validation gate. That split — "AI extracts;
deterministic logic scores" in the PRD — was an assumption when it was written. It is now a result.

**The 13 claims found only by the model are still worth reading.** Extra recall in the right places is
a genuine strength, and a hybrid — model recall, with promotions above `ASSISTED` requiring
corroboration — is the obvious next experiment. What is not defensible is shipping the model's
extraction as-is because it sounds better in a sentence.

Reproduce it:

```bash
AI_PROVIDER=deterministic python -m scripts.seed_demo && python -m scripts.run_evaluation
AI_PROVIDER=cached EXTRACTION_CACHE_FILE=chain_cache.json python -m scripts.seed_demo && python -m scripts.run_evaluation
```

can be checked rather than taken on trust.
